# 西洋魔法おみくじ（iPad / Windows + EPSON TM-m30）

画面のクリスタルをタップすると、数秒の演出のあとレシートプリンターから
おみくじが1枚印刷されるキオスクアプリです。イベントブースでの使用を想定しています。
表示端末は **iPad でも、タッチ操作できる Windows 機でも動きます**
（[Windowsだけで完結する構成](#windowsだけで完結する構成ipadを使わないいちばん簡単)がいちばん簡単です）。

- 画面の意匠は `design/sample.png` から切り出した画像そのもの（描き起こしなし）
- 全12種からランダムに1枚（1周するまで同じものが出ない「袋引き」方式）
- おみくじの中身は**画像**（`images/01.png` 〜 `12.png`）を差し替えるだけ
- HTML/CSS/JavaScript のみ。ビルド不要、Mac も Xcode も不要

**画面は縦向きで使ってください。** 原画と同じ 1024px 幅の座標系で組んであり、
表示時に画面サイズへ合わせて拡大縮小して中央に置きます。横向きでも表示は崩れませんが、
左右に大きな余白が出ます。

---

## 必要なもの

| | |
|---|---|
| 表示端末 | iPad（Safari）または**タッチ操作できるWindows機**。Windows機なら配信用PCと兼用でき、iPadは不要（後述） |
| プリンター | EPSON TM-m30（型番 `-611` = USB + Ethernet + Bluetooth モデル） |
| ルーター | プリンターとiPadを同じLANに置くため。インターネット接続は不要 |
| LANケーブル | プリンター ⇔ ルーター |
| 配信用PC | このフォルダをHTTPで配信する。ノートPCでもRaspberry Piでも可。Windows機なら表示端末と兼用できる |
| 感熱ロール紙 | 80mm幅 |

> **Wi-Fi接続にしたい場合**は、別売の無線LANユニットをプリンターに装着すれば
> LANケーブルが不要になります（`OT-WL05` は製造終了。後継は `OT-WL06`）。
> Bluetooth接続はiOS Safariからは使えません（Web Bluetooth非対応。EpsonのBluetoothは
> MFi/iAP2で、ネイティブアプリからしか触れないため）。

### 構成図

```
  iPad (Safari) ──Wi-Fi──┐
                         ├── ルーター ──LAN── TM-m30
  配信用PC ──────LAN─────┘         (例: 192.168.0.100)
   http://192.168.0.50:8080/
```

## セットアップ

### 1. おみくじ画像を置く

`images/` に `01.png` 〜 `12.png` を配置します。仕様は [`images/README.md`](images/README.md) を参照。
**画像が無くてもアプリは動きます**（IDだけのプレースホルダーが印刷される）ので、
先にプリンター接続の確認を済ませておけます。

### 2. プリンターのIPアドレスを確認する

TM-m30 の電源を入れ、`Feed` ボタンを押しながら電源を入れ直すとステータスシートが
印刷され、IPアドレスが確認できます。**DHCPだと再起動でIPが変わる**ので、
ルーターのDHCP固定割り当てか、プリンター側の固定IP設定をしておいてください。

### 3. Epson ePOS SDK を配置する

[Epson のダウンロードページ](https://download.epson-biz.com/modules/pos/index.php?page=single_soft&cid=7425&pcat=52&pid=4477)
から **ePOS SDK for JavaScript** を入手し、同梱の `epos-2.js` を `js/epos-2.js` に置きます。
そのうえで `index.html` の末尾にある次の行のコメントを外します。

```html
<script src="js/epos-2.js"></script>
```

> SDKを使わずに動かすこともできます（後述の `xml` モード）。

### 4. 設定を書き換える

`js/config.js` の先頭2項目を編集します。

```js
backend: 'sdk',              // 'mock'（印刷しない）→ 'sdk' に変更
printer: { host: '192.168.0.100', ... }   // プリンターのIP
```

### 5. HTTPで配信する

配信用PCでこのフォルダをHTTPで公開します。**HTTPSではなくHTTPで配信するのが重要です。**
HTTPSページからHTTPのプリンターへはブラウザがブロックします（mixed content）。

**Windows（Pythonを入れずに済ませる）**

> そのWindows機の画面をそのままキオスクにするなら、`serve.bat` ではなく
> [`kiosk.bat`](kiosk.bat) を使ってください（管理者権限が要りません）。
> → [Windowsだけで完結する構成](#windowsだけで完結する構成ipadを使わないいちばん簡単)

同梱の [`serve.bat`](serve.bat) をダブルクリックするだけです。
中身は [`serve.ps1`](serve.ps1) を呼ぶだけの1行で、Windowsに最初から入っている
PowerShell（`System.Net.HttpListener`）でこのフォルダを配信します。追加インストールは不要です。

- UACの「このアプリがデバイスに変更を…」に **「はい」** と答えてください。
  `http://+:8080/` で待ち受ける（＝iPadから見える）には管理者権限が必要です。
  localhost だけなら不要ですが、それではiPadから開けません。
- 起動時にWindowsファイアウォールの受信規則（プライベートネットワークのみ、TCP 8080）を
  1度だけ自動で追加します。追加したくない場合は
  `powershell -ExecutionPolicy Bypass -File serve.ps1 -NoFirewall`。
- 黒い画面に **iPadで開くURL** が表示されます。`192.168.137.x` はモバイルホットスポットのアドレスです。
- ポートを変えたいときは `serve.bat -Port 8081`。
- 終了は黒い画面で `Ctrl+C`。
- **同じPCのブラウザからしか開かない場合**は `serve.bat -LocalOnly` を使ってください。
  `localhost` だけで待ち受けるので、管理者権限もファイアウォール設定も不要になります。

**macOS / Linux / Raspberry Pi**

```bash
cd omikuji
python3 -m http.server 8080 --bind 0.0.0.0
```

### 6. iPadで開く

Safari で `http://<配信用PCのIP>:8080/` を開きます。
共有ボタン →「ホーム画面に追加」でフルスクリーンのアプリとして起動できます。

### 7. 当日の運用設定（推奨）

- **設定 → アクセシビリティ → アクセスガイド** をONにし、起動後にサイドボタン3回押しで画面をロック。
  来場者が他のアプリに移動できなくなります。
- **設定 → 画面表示と明るさ → 自動ロック → なし**
- iPadとプリンターの電源（モバイルバッテリー等）を確保

## Windowsだけで完結する構成（iPadを使わない・いちばん簡単）

**タッチ操作できるWindows機（Surface等）があれば、iPadは不要です。**
アプリはブラウザで動くので、同じPCのEdgeで開けばそれでキオスクになります。
ルーターもWi-Fiもホットスポットも要らず、**LANケーブル1本**で済みます。

```
  Surface（画面＋配信＋印刷指示）──LANケーブル──USB有線LANアダプタ──── TM-m30
        Edge キオスクモード                         192.168.10.100
        http://localhost:8080/
```

この構成の利点:

- **モバイルホットスポットが要らない** ＝ 「インターネットの無い回線を共有できるか」という
  いちばんの不確定要素が消える
- 管理者権限もファイアウォール設定も不要（`localhost` だけで待ち受けるため）
- 無線が一切絡まないので、会場の電波混雑の影響を受けない

### 手順

1. **USB有線LANアダプタ**でPCとTM-m30をLANケーブル直結（ハブ不要）
2. **両側に固定IPを振る** → [固定IPの振り方](#固定ipの振り方)
   （PCとプリンターを直結するとDHCPサーバーが居ないので、自動取得はできません）
3. **[`kiosk.bat`](kiosk.bat) をダブルクリック。**
   `serve.ps1` を `localhost` 限定で起動し、Edgeをキオスクモード（全画面・タブもURL欄も無し）で開きます。
   UACのプロンプトは出ません。
4. **画面右上を1.5秒長押し**して設定パネルを開き、
   印刷方式 `xml`（SDKを置いていれば `sdk`）、プリンターのIP `192.168.10.100` を入力して保存
5. 「テスト印刷」で1枚出れば完成

キオスクを抜けるときはEdgeの画面で `Ctrl+W`（または `Alt+F4`）。
配信を止めるときは黒い画面で `Enter`。

### 固定IPの振り方

順番が大事です。**プリンターを設定しに行くのではなく、まずプリンターが今どうなっているかを
紙に吐かせて、それに合わせてPCを寄せる**のが確実です。プリンター側を触るのは最後です。

#### ① プリンターの現在のIPを、ステータスシートで確認する

TM-m30 の電源を切り、**`Feed` ボタンを押しながら電源を入れる**と設定内容が印刷されます。
`IP Address` と `Subnet Mask`、それに `Get IP Address`（`Auto` = DHCP / `Manual` = 固定）を見ます。

- 工場出荷状態は `Auto`（DHCP）です。PC直結ではDHCPサーバーが居ないので取得に失敗し、
  `(NONE)` のまま／`169.254.x.x`（APIPA）／機種の既定IP（`192.168.192.168`）のいずれかになります。
  **どれになるかは設定とファームウェア次第なので、必ず紙に出た実際の値を使ってください。**
- ケーブルを挿してから値が確定するまで1分ほどかかります。
  **LANケーブルを繋いだ状態で**電源を入れ、少し待ってからシートを出してください
  （ケーブル未接続だと必ず `(NONE)` になります）。
- `Wi-Fi MAC Address` が `Unmounted` なら無線ユニットは未装着で、ネットワークは有線のみです。

#### ①-b `IP Address` が `(NONE)` だったとき

「取りに行ったが取れていない」状態です。**アドレスが分からないのではなく、そもそも無い**ので、
こちらから与えます。楽な順に3通りあります。

**（a） 自宅のルーターにいったん繋ぐ ← いちばん早い**

イベント会場ではなく自宅で、**プリンターのLANポートと自宅のルーターをLANケーブルで繋ぎます。**
ルーターにはDHCPサーバーが居るので、1分ほどでアドレスが降ってきます。

1. 繋いだまま電源を入れ直し、1分待ってステータスシートを出す → `IP Address` に値が入ります
2. 同じWi-Fiに繋がったPCのEdgeで **`http://<その IP>/`** を開く（プリンターのWeb設定画面）
3. ネットワーク設定を **`Manual`（固定）** にして、`192.168.10.100` / `255.255.255.0` を設定、
   **ゲートウェイは空欄**にして保存 → 電源を入れ直す
4. ルーターから外し、PCの有線LANアダプタに直結する

以後は電源を入れ直しても `192.168.10.100` のままです。**ツールのダウンロードが一切要りません。**

**（b） PCに直結して、何を名乗るか見る**

先にPC側へ固定IPを振ってから（→ ②）、プリンターを直結して電源を入れ直し、1分待って
ステータスシートを出し直します。

- `169.254.x.x` になった … APIPAです。PC側にも `169.254.0.1` / `255.255.0.0` を振れば通信できます。
  通ったらWeb設定画面から `Manual` に直してください。
- `192.168.192.168` になった … 機種の既定IPです。PC側を `192.168.192.10` / `255.255.255.0` に。
- `(NONE)` のまま … （c）へ。

**（c） EpsonNet Config でMACアドレス指定で押し込む**

Epsonの設定ツール **EpsonNet Config**（Windows版、Epsonのダウンロードページから入手）は、
**IPを持っていない機器もMACアドレスで見つけて**アドレスを書き込めます。
ステータスシートの `Ethernet MAC Address`（例 `64-EB-8C-FE-B0-F4`）が目印です。
PCとプリンターを直結し、PC側に固定IPを振った状態で起動すると一覧に出てきます。

> ステータスシート末尾の `Mode Selection : 1 second or more` から入るモード選択メニューには、
> ネットワーク設定を工場出荷状態に戻す項目もあります。設定を触りすぎて分からなくなったときの
> 逃げ道として覚えておいてください。

#### ② PCの有線LANアダプタに、それと同じ並びの固定IPを振る

シートが `192.168.192.168 / 255.255.255.0` だったなら、PC側は
**第3オクテットまで同じで、最後だけ別の番号**にします（例 `192.168.192.10`）。

**設定アプリから（おすすめ）**

1. `Windowsキー + R` → `ncpa.cpl` → Enter（ネットワーク接続の一覧が開きます）
2. USB有線LANアダプタ（`イーサネット 2` などの名前になっています）を右クリック → **プロパティ**
3. **インターネット プロトコル バージョン 4 (TCP/IPv4)** を選んで **プロパティ**
4. **「次のIPアドレスを使う」** を選び、

   | 項目 | 値 |
   |---|---|
   | IPアドレス | `192.168.192.10`（プリンターと同じ並びの別番号） |
   | サブネットマスク | `255.255.255.0` |
   | デフォルトゲートウェイ | **空欄のまま** |
   | 優先DNSサーバー | **空欄のまま** |

5. OK → OK

> **ゲートウェイとDNSを空欄にするのが重要です。** この配線の先にインターネットは無いので、
> 埋めるとWindowsが「こっちが本命の回線だ」と判断して、Wi-Fi側の通信まで巻き込んで不安定になります。
> 空欄にしておけば、**Wi-Fiのインターネットはそのまま使えたまま**、有線側はプリンター専用の
> 閉じた線として共存します。

**コマンドで済ませたい場合**（PowerShellを管理者で開いて）

```powershell
# アダプタの正確な名前を調べる
Get-NetAdapter | Format-Table Name, InterfaceDescription, Status

# 固定IPを振る（名前は上で調べたものに置き換え）
netsh interface ip set address name="イーサネット 2" static 192.168.192.10 255.255.255.0

# 元に戻す（自動取得へ）
netsh interface ip set address name="イーサネット 2" dhcp
```

#### ③ 通ったか確かめる

同梱の [`netcheck.bat`](netcheck.bat) をダブルクリックし、プリンターのIPを入れてください。
「PCのIP一覧 → 同じセグメントか → ping → TCP 80 → ePOS-Printへの送信」を順に試して、
**どこで止まっているか**を日本語で表示します。最後に1ドットだけ紙送りするので、
プリンターがカタッと動けば経路は完全に通っています。

```
netcheck.bat -Printer 192.168.192.168
```

#### ④ プリンター側を固定にしておく（推奨）

②③が通ったら、Edgeで **`http://<プリンターのIP>/`** を開くと本体のWeb設定画面が出ます。
ネットワーク設定を **`Manual`（固定）** にして、覚えやすいアドレス（例 `192.168.10.100`）を
決めておくと、以後は電源を入れ直しても同じアドレスになります。
そのときはPC側も同じ並び（例 `192.168.10.1`）に振り直してください。

> Web設定画面が出ない機種・ファームウェアの場合は、Epsonの
> **EpsonNet Config**（Windows用の設定ツール）を使います。別セグメントに居るプリンターも
> 見つけてくれるので、IPが分からなくなったときの最後の手段としても使えます。

> **どうしても繋がらないとき**は、ステータスシートを出し直して
> `Get IP Address` と `IP Address` の実際の値を教えてください。そこから切り分けます。

### 当日の設定（Windows）

- **設定 → システム → 電源とバッテリー → 画面とスリープ** をすべて「なし」に
- **設定 → システム → ディスプレイ → 画面の向き** を「縦」にすると原画の比率にぴったり合います
  （横のままでも画面中央に収まるように作ってあります）
- タッチキーボードが出て邪魔な場合は、アプリ側に文字入力欄が無いので通常は出ません

> **画面の大きさについて。** アプリは 1024×1164 の座標系で組んであり、
> ウィンドウの大きさに合わせて自動で拡大縮小して中央に置かれます。
> Surface Pro 6（2736×1824）の全画面でも問題なく収まります。

### プリンター側の接続について

TM-m30-611 は USB でもPCに繋がりますが、**このアプリはUSB接続では印刷できません**。
ブラウザから叩いているのはプリンター内蔵のWebサービス（ePOS-Print）で、
これはEthernet（またはWi-Fiユニット）でしか公開されないためです。
**USBケーブルではなくLANケーブルで繋いでください。**

> どうしてもUSBで済ませたい場合は、EpsonのWindowsドライバ（APD）を入れて
> ブラウザの印刷機能から刷る、という別方式になります。用紙カットや位置の制御が
> ドライバ任せになるぶん作り込みが必要なので、まずはLAN接続を試してください。

## ルーターを持ち込まない構成（ノートPCがルーター役）

イベント会場にルーターを持ち込みたくない場合、**ノートPC1台でルーター役と配信役を
兼ねられます**。プリンターは有線LANで直結し、iPadはノートPCのモバイルホットスポットに繋ぎます。

```
  iPad ──Wi-Fi（PCのモバイルホットスポット）──┐
                                              ノートPC（ルーター役＋配信役）
  TM-m30 ──LANケーブル──USB有線LANアダプタ────┘
```

> Surface Pro 6 など USB-C の無い機種では、**USB-A の有線LANアダプタ**が必要です。

### 手順（Windows）

1. **有線LANアダプタをPCに挿し、LANケーブルでTM-m30と直結する。**
   ハブは不要です（今どきのNICはクロスケーブル不要）。
2. **プリンターとPCのEthernet側に固定IPを振る。** 手順は
   [固定IPの振り方](#固定ipの振り方)と同じです。
3. **モバイルホットスポットをONにする。**
   「設定 → ネットワークとインターネット → モバイルホットスポット」。
   iPadをそのSSIDに接続すると、iPadは `192.168.137.x`、PC側は `192.168.137.1` になります。
4. **`serve.bat` を実行し、表示された `http://192.168.137.1:8080/` をiPadのSafariで開く。**
5. **アプリの設定パネル（右上を1.5秒長押し）でプリンターのIPを `192.168.10.100` にする。**
   印刷方式は `xml`（SDKを置いていれば `sdk`）。

### 事前に必ず確認しておくこと

- **モバイルホットスポットが「インターネットの無いEthernet」でも起動するか。**
  Windowsのモバイルホットスポットは「共有する接続」を選ばせる作りのため、
  インターネットに出られない接続だと起動を拒む場合があります。
  会場ではなく自宅で先に試してください。
  起動しない場合の代替は次の2つです。
  - PCをスマホのテザリングに繋ぎ、**それ**をホットスポットで共有する（＝インターネットあり）
  - モバイルホットスポットを諦めて、小型のトラベルルーター／モバイルルーターを1台持ち込む
- **iPad側でSafariが `http://` を開けるか。** 「プライベートリレー」がONだと
  ローカルIPへのアクセスが妨げられることがあります。当日はOFFにしておくと安全です。
- **PCがスリープしないか。** 「電源とバッテリー → 画面とスリープ」を「なし」に。

## 画面の使い方

- 中央のクリスタルをタップ → 約3秒の演出（魔法陣が回り、クリスタルが光る）
  → 印刷 → 結果表示 → 待機に戻る
- 印刷に失敗したときは画面上部に理由が出ます。画面のどこかに触れると待機に戻ります
  （20秒で自動的に戻ります）
- **画面右上を1.5秒長押し**すると設定パネルが開きます（来場者が誤って開かないよう隠しています）
  - 印刷方式・プリンターIP・ポートの変更（この端末に保存され、`config.js` より優先されます）
  - **テスト印刷**
  - **抽選のリセット**（袋を空にして12種すべてを引き直せる状態に戻す）
  - **おみくじの履歴**（本日の枚数・累計・種別の内訳。当日の集計に使えます）

来場者に見える画面には履歴を出していません。履歴はこの設定パネルの中だけにあります。

## 設定項目（`js/config.js`）

| 項目 | 説明 |
|---|---|
| `backend` | `'mock'` 印刷せず画面プレビューのみ／`'sdk'` ePOS SDK経由（推奨）／`'xml'` ePOS-Print XMLを直接POST |
| `printer.host` | プリンターのIPアドレス |
| `printer.sdkPort` | ePOS-Device Service のポート。平文 `8008` / SSL `8043` |
| `paper.widthDots` | 印字幅。80mm紙は `576`、58mm紙は `420`（8の倍数であること） |
| `print.halftone` | `'dither'` / `'threshold'` / `'error_diffusion'`（`sdk` 時のみ） |
| `print.brightness` | 濃度 0.1〜10.0（`sdk` 時のみ）。薄いときは上げる |
| `print.invertBits` | 白黒が反転して出た場合に `true` |
| `print.feedUnitsAfter` | 印字後の紙送り量（ドット）。カット位置の調整用 |
| `print.footer` | 画像の下に共通のテキスト・QRコード（BOOTHへの導線など）を刷る |
| `draw.mode` | `'bag'` 1周まで重複なし／`'weighted'` 毎回独立の重み付き抽選 |
| `items[].weight` | 出現の重み。`bag` では袋に入れる枚数、`weighted` では確率の比 |

### 出現率を変えたいとき

```js
draw: { mode: 'weighted' },
items: [
  { id: '01', label: '大吉', image: 'images/01.png', weight: 0.5 },  // 出にくくする
  { id: '02', label: '吉',   image: 'images/02.png', weight: 2 },    // 出やすくする
  ...
]
```

## SDKを使わない `xml` モード

`epos-2.js` を用意せずに動かしたい場合は `backend: 'xml'` にします。
画像をブラウザ側で1bitラスターに変換し、ePOS-Print XML をプリンターに直接POSTします。

- 追加ファイル不要
- 濃度・ハーフトーンの細かい調整はできない（アプリ内の誤差拡散ディザ固定）
- 白黒が反転する場合は設定パネルの「白黒を反転して印刷する」をON

実運用では、Epson が動作保証している `sdk` モードを推奨します。

## うまく動かないとき

| 症状 | 対処 |
|---|---|
| 「epos-2.js が読み込まれていません」 | 手順3。`index.html` の `<script src="js/epos-2.js">` のコメントを外したか確認 |
| 「プリンターに接続できません」 | IPが正しいか、表示端末とプリンターが同じLANにいるか、ポート（8008）が合っているかを確認。ブラウザで `http://<IP>/` を開くとプリンターの設定画面が出ます |
| ブラウザのコンソールに CORS のエラーが出る | `xml` モードはブラウザから別オリジン（プリンター）へPOSTするため、プリンター側がCORSに応答する必要があります。TM-m30 のePOS-Printは対応していますが、本体のWeb設定でePOS-Printサービスが有効になっているか確認してください。解決しない場合は `sdk` モード（WebSocket。CORSの制約を受けません）に切り替えます |
| Windowsで印刷だけ動かない | **USBケーブルでは印刷できません。**このアプリはプリンター内蔵のWebサービスを叩くので、Ethernet（LANケーブル）接続が必要です |
| ページは開くが印刷だけ失敗する | ページをHTTPSで配信していないか確認（mixed content）。HTTPで配信すること |
| 「用紙がありません」 | ロール紙を補充。カバーを確実に閉じる |
| 印字が薄い / 濃すぎる | `print.brightness` を調整（`sdk` 時）。または画像側のコントラストを上げる |
| 白黒が反転する | `print.invertBits` を `true` に |
| 画像が荒い | [`images/README.md`](images/README.md) の作画のコツを参照。幅576pxで作り直すと改善します |
| 同じおみくじばかり出る | `draw.mode: 'bag'` になっているか確認。設定パネルの「抽選をリセット」で袋を作り直せます |
| 画面の飾りが出ない | `assets/` が空の可能性があります。`python3 tools/slice_assets.py` を実行してください |
| Windowsで画面の左右に余白が出る | 横向き（3:2）の画面に縦長の原画を収めているためです。ディスプレイの向きを「縦」にすると余白が消えます。動作上の問題はありません |
| 画面が窓より大きく表示され、設定ボタンに届かない | ファイルアプリのプレビューは viewport 指定を無視します。visualViewport の実寸で拡大率を出すよう対応済みなので、最新の1ファイル版を使ってください |
| 書体が違って見える | `fonts/*.woff2` が配信されているか確認。同梱フォントが読めないと端末の明朝にフォールバックします |

## デザイン

画面の装飾はすべて原画から切り出した画像です。SVG等での描き起こしはしていません。

| 原画 | 用途 |
|---|---|
| `design/sample.png` | 画面全体のデザイン。枠・紋章・カード・城の背景など |
| `design/maho.png` | 魔法陣。`sample` 側の魔法陣は縦横比0.935の楕円に歪んでいて、回すと膨らみ縮みして見えるため、真円のこちらを使う |

切り出しは次のスクリプトが行います。

```bash
pip install Pillow
python3 omikuji/tools/slice_assets.py
```

`assets/*.png`（パーツ画像）と `css/assets.css`（配置座標）が再生成されます。
**`css/assets.css` は自動生成なので直接編集しないでください。**
文字だけはHTMLで組んでいるので、拡大してもぼやけず、状態に応じて差し替えられます。

切り出しでは次の処理をしています。

- クリーム地や空の上に描かれた線画は、**地色からの色差をアルファに変換**して透過で抜く
  （アンチエイリアスが保たれる）
- 魔法陣は `maho.png` から**ルーン環**と**中心（光条＋クリスタル）**に分ける。
  どちらも**中心が画像のど真ん中に来る正方形**で切り出す。外接矩形に詰めると
  回転中心が数pxずれ、回したときに振れて見えるため
- リボンは空と城の上にあるので、色差で抜いたあと**最大の連結成分だけを残して**
  周囲の雲や城の切れ端を落とす
- 背景の城バンドからは、重ねて動かす魔法陣とクリスタルを**ぼかして消し込む**。
  リボンは動かさないので背景に焼いたまま残し、同じ位置に画像を重ねている。
  こうすると回る環がリボンの奥に入り、原画通りの前後関係になる

### 座標の書き方

切り出し範囲はすべて**設計座標 1024×1536** で書いてあります。原画がこれより
大きくても（現在の `sample.png` は 2000×3000）スクリプトが自動で換算するので、
**原画を高解像度のものに差し替えても座標定数はそのままで動きます**。
パーツ画像は原画の解像度のまま出力されるので、そのぶん精細になります。

原画のレイアウトそのものが変わった場合は、`tools/slice_assets.py` の
`PARTS` / `SIGIL_*` / `RIBBON_*` を実測値に合わせて調整してください。

### 書体

見出し・本文は **Sawarabi Mincho**（SIL Open Font License 1.1）です。
**Google Fonts の CDN からは読まず、`fonts/` に同梱したものを使っています。**
会場のLANはインターネットに繋がない構成なので、CDN参照だと当日フォントが
落ちてこず、別の書体で表示されてしまうためです。

- `css/fonts.css` … Google Fonts が配る `unicode-range` 付き118分割をそのまま
  ローカル参照に書き換えたもの。実際に使う字が入ったファイルだけが読まれます
  （この画面なら11ファイル・約130KB。同梱の合計は約1MB）
- Sawarabi Mincho はウェイトが1種類（400）だけなので、見出しに `font-weight` は
  指定していません。指定するとブラウザが合成太字を作り、明朝の線が濁ります
- ラテン文字（ARCANE FORTUNE / Omikuji of Western Magic）は原画が欧文セリフなので、
  `--latin`（Palatino系）のままにしてあります。和文と揃えたい場合は
  `css/style.css` の `--latin` を `var(--mincho)` に変えてください

### ページの詰め具合

「おみくじの種類」を外したぶん、フッター一式（一文・クレジット・円形紋章・
下辺の枠・下の角飾り）をまとめて上に寄せています。寄せ幅は
`css/style.css` の `--footer-shift`（現在 372px）ひとつで調整できます。
`0` にすると原画どおりの位置に戻ります。

フッターはこの値ぶんだけ群ごと動かすので、`css/assets.css`（自動生成）の
座標を書き換える必要はありません。ページの高さもこの値から自動で決まります。

詰めるとページが縦に短くなるぶん、iPadの画面には上下に余白が出ます
（同じ紙地なので、額装の余白のように見えます）。

### デザインと変えたところ

- フッターのクレジットを `© 2026 Ceria fi Ixtigna` に差し替え（タイトルは原画のまま）
- 「おみくじの履歴を見る」ボタンは画面から外し、スタッフ用の設定パネルに移動
- 「おみくじの種類」のカード一覧は画面から削除（原画には5種のカードがあります）

## 1ファイル版（配信用PCを使わない構成）

`dist/omikuji-standalone.html` は、画像・フォント・CSS・JS をすべて埋め込んだ
**単体で動くHTMLファイル**です（約2MB）。iPadの「ファイル」アプリに置いて
直接開けば、Webサーバーを立てずに動きます。

```bash
pip install Pillow
python3 omikuji/tools/build_single_file.py
```

- 印刷方式は `xml` が既定（SDK不要）。IPは設定パネルから入れます
- `images/01.png`〜`12.png` があれば、それも一緒に埋め込まれます
- 大きい画像は非可逆WebPに、フォントは実際に使う字が入ったサブセットだけに
  絞って埋め込むので、2MB程度に収まります

**`file://` で開いたページからプリンターへ通信できるかはブラウザ次第です。**
Chromium では通ることを確認しましたが、iPad の Safari は制限が厳しいため、
実機での確認が必要です。通らない場合は配信用PCを置く従来の構成に戻してください。

有線LANで直結する場合は、iPadに**LAN＋PD給電が一体のUSB-Cハブ**を挿し、
プリンターとiPadの両方に固定IPを振ります（DHCPサーバーがいないため）。

## 開発メモ

プリンターが手元に無くても `backend: 'mock'` のまま
`python3 -m http.server 8080` で開けば、演出と抽選、印刷される画像のプレビューまで
一通り確認できます。

```
omikuji/
├── index.html
├── css/style.css     画面のスタイル
├── css/assets.css    パーツの配置座標（自動生成）
├── js/config.js      設定（ここだけ編集すればよい）
├── js/raster.js      画像の読み込み・リサイズ・1bitラスター化（誤差拡散ディザ）
├── js/printer.js     印刷バックエンド（sdk / xml / mock）
├── js/draw.js        抽選（袋引き・重み付き）
├── js/app.js         画面遷移とフロー

├── fonts/            同梱フォント（Sawarabi Mincho, OFL 1.1）

├── dist/             1ファイル版（自動生成）
└── images/           おみくじ画像 01.png〜12.png（印刷される中身）
```
