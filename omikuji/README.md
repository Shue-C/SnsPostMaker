# 西洋魔法おみくじ（iPad + EPSON TM-m30）

iPadの画面のクリスタルをタップすると、数秒の演出のあとレシートプリンターから
おみくじが1枚印刷されるキオスクアプリです。イベントブースでの使用を想定しています。

- 画面の意匠は `design/sample.png` から切り出した画像そのもの（描き起こしなし）
- 全12種からランダムに1枚（1周するまで同じものが出ない「袋引き」方式）
- おみくじの中身は**画像**（`images/01.png` 〜 `12.png`）を差し替えるだけ
- HTML/CSS/JavaScript のみ。ビルド不要、Mac も Xcode も不要

**iPadは縦向きで使ってください。** 画面は原画と同じ 1024×1536 の比率で組んであり、
表示時に画面サイズへ合わせて拡大縮小します。横向きでも表示は崩れませんが、
左右に大きな余白が出ます。

---

## 必要なもの

| | |
|---|---|
| iPad | Safari が動けば世代は問わない |
| プリンター | EPSON TM-m30（型番 `-611` = USB + Ethernet + Bluetooth モデル） |
| ルーター | プリンターとiPadを同じLANに置くため。インターネット接続は不要 |
| LANケーブル | プリンター ⇔ ルーター |
| 配信用PC | このフォルダをHTTPで配信する。ノートPCでもRaspberry Piでも可 |
| 感熱ロール紙 | 80mm幅 |

> **Wi-Fi接続にしたい場合**は、別売の無線LANユニット `OT-WL05` をプリンターに
> 装着すればLANケーブルが不要になります。Bluetooth接続はiOS Safariからは使えません
> （Web Bluetooth非対応のため）。Bluetoothで繋ぎたい場合はネイティブアプリが必要です。

### 構成図

```
  iPad (Safari) ──Wi-Fi──┐
                         ├── ルーター ──LAN── TM-m30
  配信用PC ──────LAN─────┘         (例: 192.168.0.100)
   http://192.168.0.50:8080/
```

## セットアップ

### 1. おみくじ画像を置く

`images/` に `01.png` 〜 `12.png` を配置します。仕様は [`images/README.md`](images/README.md) を参照。
**画像が無くてもアプリは動きます**（IDだけのプレースホルダーが印刷される）ので、
先にプリンター接続の確認を済ませておけます。

### 2. プリンターのIPアドレスを確認する

TM-m30 の電源を入れ、`Feed` ボタンを押しながら電源を入れ直すとステータスシートが
印刷され、IPアドレスが確認できます。**DHCPだと再起動でIPが変わる**ので、
ルーターのDHCP固定割り当てか、プリンター側の固定IP設定をしておいてください。

### 3. Epson ePOS SDK を配置する

[Epson のダウンロードページ](https://download.epson-biz.com/modules/pos/index.php?page=single_soft&cid=7425&pcat=52&pid=4477)
から **ePOS SDK for JavaScript** を入手し、同梱の `epos-2.js` を `js/epos-2.js` に置きます。
そのうえで `index.html` の末尾にある次の行のコメントを外します。

```html
<script src="js/epos-2.js"></script>
```

> SDKを使わずに動かすこともできます（後述の `xml` モード）。

### 4. 設定を書き換える

`js/config.js` の先頭2項目を編集します。

```js
backend: 'sdk',              // 'mock'（印刷しない）→ 'sdk' に変更
printer: { host: '192.168.0.100', ... }   // プリンターのIP
```

### 5. HTTPで配信する

配信用PCでこのフォルダを開き、次を実行します。

```bash
cd omikuji
python3 -m http.server 8080 --bind 0.0.0.0
```

**HTTPSではなくHTTPで配信するのが重要です。** HTTPSページからHTTPのプリンターへは
ブラウザがブロックします（mixed content）。

### 6. iPadで開く

Safari で `http://<配信用PCのIP>:8080/` を開きます。
共有ボタン →「ホーム画面に追加」でフルスクリーンのアプリとして起動できます。

### 7. 当日の運用設定（推奨）

- **設定 → アクセシビリティ → アクセスガイド** をONにし、起動後にサイドボタン3回押しで画面をロック。
  来場者が他のアプリに移動できなくなります。
- **設定 → 画面表示と明るさ → 自動ロック → なし**
- iPadとプリンターの電源（モバイルバッテリー等）を確保

## 画面の使い方

- 中央のクリスタルをタップ → 約3秒の演出（魔法陣が回り、クリスタルが光る）
  → 印刷 → 結果表示 → 待機に戻る
- 印刷に失敗したときは画面上部に理由が出ます。画面のどこかに触れると待機に戻ります
  （20秒で自動的に戻ります）
- **画面右上を1.5秒長押し**すると設定パネルが開きます（来場者が誤って開かないよう隠しています）
  - 印刷方式・プリンターIP・ポートの変更（この端末に保存され、`config.js` より優先されます）
  - **テスト印刷**
  - **抽選のリセット**（袋を空にして12種すべてを引き直せる状態に戻す）
  - **おみくじの履歴**（本日の枚数・累計・種別の内訳。当日の集計に使えます）

来場者に見える画面には履歴を出していません。履歴はこの設定パネルの中だけにあります。

---

## 設定項目（`js/config.js`）

| 項目 | 説明 |
|---|---|
| `backend` | `'mock'` 印刷せず画面プレビューのみ／`'sdk'` ePOS SDK経由（推奨）／`'xml'` ePOS-Print XMLを直接POST |
| `printer.host` | プリンターのIPアドレス |
| `printer.sdkPort` | ePOS-Device Service のポート。平文 `8008` / SSL `8043` |
| `paper.widthDots` | 印字幅。80mm紙は `576`、58mm紙は `420`（8の倍数であること） |
| `print.halftone` | `'dither'` / `'threshold'` / `'error_diffusion'`（`sdk` 時のみ） |
| `print.brightness` | 濃度 0.1〜10.0（`sdk` 時のみ）。薄いときは上げる |
| `print.invertBits` | 白黒が反転して出た場合に `true` |
| `print.feedUnitsAfter` | 印字後の紙送り量（ドット）。カット位置の調整用 |
| `print.footer` | 画像の下に共通のテキスト・QRコード（BOOTHへの導線など）を刷る |
| `draw.mode` | `'bag'` 1周まで重複なし／`'weighted'` 毎回独立の重み付き抽選 |
| `items[].weight` | 出現の重み。`bag` では袋に入れる枚数、`weighted` では確率の比 |

### 出現率を変えたいとき

```js
draw: { mode: 'weighted' },
items: [
  { id: '01', label: '大吉', image: 'images/01.png', weight: 0.5 },  // 出にくくする
  { id: '02', label: '吉',   image: 'images/02.png', weight: 2 },    // 出やすくする
  ...
]
```

## SDKを使わない `xml` モード

`epos-2.js` を用意せずに動かしたい場合は `backend: 'xml'` にします。
画像をブラウザ側で1bitラスターに変換し、ePOS-Print XML をプリンターに直接POSTします。

- 追加ファイル不要
- 濃度・ハーフトーンの細かい調整はできない（アプリ内の誤差拡散ディザ固定）
- 白黒が反転する場合は設定パネルの「白黒を反転して印刷する」をON

実運用では、Epson が動作保証している `sdk` モードを推奨します。

## うまく動かないとき

| 症状 | 対処 |
|---|---|
| 「epos-2.js が読み込まれていません」 | 手順3。`index.html` の `<script src="js/epos-2.js">` のコメントを外したか確認 |
| 「プリンターに接続できません」 | IPが正しいか、iPadとプリンターが同じLANにいるか、ポート（8008）が合っているかを確認。ブラウザでは `http://<IP>/` を開くとプリンターの設定画面が出ます |
| ページは開くが印刷だけ失敗する | ページをHTTPSで配信していないか確認（mixed content）。HTTPで配信すること |
| 「用紙がありません」 | ロール紙を補充。カバーを確実に閉じる |
| 印字が薄い / 濃すぎる | `print.brightness` を調整（`sdk` 時）。または画像側のコントラストを上げる |
| 白黒が反転する | `print.invertBits` を `true` に |
| 画像が荒い | [`images/README.md`](images/README.md) の作画のコツを参照。幅576pxで作り直すと改善します |
| 同じおみくじばかり出る | `draw.mode: 'bag'` になっているか確認。設定パネルの「抽選をリセット」で袋を作り直せます |
| 画面の飾りが出ない | `assets/` が空の可能性があります。`python3 tools/slice_assets.py` を実行してください |
| 書体が違って見える | `fonts/*.woff2` が配信されているか確認。同梱フォントが読めないと端末の明朝にフォールバックします |

## デザイン

画面の装飾はすべて原画から切り出した画像です。SVG等での描き起こしはしていません。

| 原画 | 用途 |
|---|---|
| `design/sample.png` | 画面全体のデザイン。枠・紋章・カード・城の背景など |
| `design/maho.png` | 魔法陣。`sample` 側の魔法陣は縦横比0.935の楕円に歪んでいて、回すと膨らみ縮みして見えるため、真円のこちらを使う |

切り出しは次のスクリプトが行います。

```bash
pip install Pillow
python3 omikuji/tools/slice_assets.py
```

`assets/*.png`（パーツ画像）と `css/assets.css`（配置座標）が再生成されます。
**`css/assets.css` は自動生成なので直接編集しないでください。**
文字だけはHTMLで組んでいるので、拡大してもぼやけず、状態に応じて差し替えられます。

切り出しでは次の処理をしています。

- クリーム地や空の上に描かれた線画は、**地色からの色差をアルファに変換**して透過で抜く
  （アンチエイリアスが保たれる）
- 魔法陣は `maho.png` から**ルーン環**と**中心（光条＋クリスタル）**に分ける。
  どちらも**中心が画像のど真ん中に来る正方形**で切り出す。外接矩形に詰めると
  回転中心が数pxずれ、回したときに振れて見えるため
- リボンは空と城の上にあるので、色差で抜いたあと**最大の連結成分だけを残して**
  周囲の雲や城の切れ端を落とす
- 背景の城バンドからは、重ねて動かす魔法陣とクリスタルを**ぼかして消し込む**。
  リボンは動かさないので背景に焼いたまま残し、同じ位置に画像を重ねている。
  こうすると回る環がリボンの奥に入り、原画通りの前後関係になる

### 座標の書き方

切り出し範囲はすべて**設計座標 1024×1536** で書いてあります。原画がこれより
大きくても（現在の `sample.png` は 2000×3000）スクリプトが自動で換算するので、
**原画を高解像度のものに差し替えても座標定数はそのままで動きます**。
パーツ画像は原画の解像度のまま出力されるので、そのぶん精細になります。

原画のレイアウトそのものが変わった場合は、`tools/slice_assets.py` の
`PARTS` / `SIGIL_*` / `RIBBON_*` を実測値に合わせて調整してください。

### 書体

見出し・本文は **Sawarabi Mincho**（SIL Open Font License 1.1）です。
**Google Fonts の CDN からは読まず、`fonts/` に同梱したものを使っています。**
会場のLANはインターネットに繋がない構成なので、CDN参照だと当日フォントが
落ちてこず、別の書体で表示されてしまうためです。

- `css/fonts.css` … Google Fonts が配る `unicode-range` 付き118分割をそのまま
  ローカル参照に書き換えたもの。実際に使う字が入ったファイルだけが読まれます
  （この画面なら11ファイル・約130KB。同梱の合計は約1MB）
- Sawarabi Mincho はウェイトが1種類（400）だけなので、見出しに `font-weight` は
  指定していません。指定するとブラウザが合成太字を作り、明朝の線が濁ります
- ラテン文字（ARCANE FORTUNE / Omikuji of Western Magic）は原画が欧文セリフなので、
  `--latin`（Palatino系）のままにしてあります。和文と揃えたい場合は
  `css/style.css` の `--latin` を `var(--mincho)` に変えてください

### デザインと変えたところ

- フッターのクレジットを `© 2026 Ceria fi Ixtigna` に差し替え（タイトルは原画のまま）
- 「おみくじの履歴を見る」ボタンは画面から外し、スタッフ用の設定パネルに移動
- 「おみくじの種類」のカード一覧は画面から削除（原画には5種のカードがあります）

## 開発メモ

プリンターが手元に無くても `backend: 'mock'` のまま
`python3 -m http.server 8080` で開けば、演出と抽選、印刷される画像のプレビューまで
一通り確認できます。

```
omikuji/
├── index.html
├── css/style.css     画面のスタイル
├── css/assets.css    パーツの配置座標（自動生成）
├── js/config.js      設定（ここだけ編集すればよい）
├── js/raster.js      画像の読み込み・リサイズ・1bitラスター化（誤差拡散ディザ）
├── js/printer.js     印刷バックエンド（sdk / xml / mock）
├── js/draw.js        抽選（袋引き・重み付き）
├── js/app.js         画面遷移とフロー
├── design/           デザイン原画
├── fonts/            同梱フォント（Sawarabi Mincho, OFL 1.1）
├── assets/           原画から切り出したパーツ（自動生成）
├── tools/            切り出しスクリプト
└── images/           おみくじ画像 01.png〜12.png（印刷される中身）
```
